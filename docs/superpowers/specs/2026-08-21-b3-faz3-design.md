## 1. Problem

B3 (`da59ef871`, `b3bd89f3b`) sınav konu kırılımını **ders bazından konu bazına**
çevirdi: `KonuPerformansi.konu` artık `"matematik"` değil `"Fonksiyonlar"` taşıyor.
Kardinalite `1 kova → 13/14 kova` oldu.

FAZ 2 doğrudan tüketicileri onardı. **Bir katman yukarıda üç kusur açık kaldı** —
üçü de aynı kök nedene bağlı:

> `KonuPerformansi` (`backend/models/exam.py:83`) yalnız `konu: str` taşır.
> **Ders kimliği için ayrı alan yoktur.** Ders kimliğine ihtiyacı olan her tüketici
> `konu` dizesini ders sanmak zorunda kaldı.

Bu, S243'te deftere yazılan dersin (`L-s241-kardinalite-degisiminde-SAYAN-tuketici`)
ikinci dalgasıdır: *kardinalite değiştiren değişikliğin en kırılgan tüketicisi listeyi
OKUYAN değil, etiketi ANAHTAR SANAN koddur.*

`backend/config/mock_endpoint_flags.json` okundu: **tüm `advanced_reports.*`

(a)'yı *"bugün öğrenciyi bozuyor"* diye raporlamak aşırı iddia olurdu. Gerçek bir
kusurdur ve düzeltilir; ama kanıtı **uç üzerinden değil doğrudan sorgu ile**
üretilir. Bu ayrım denetim dokümanına geçirilir.

### 1.2 Çürütülen hipotez (dürüst kayıt)

Tasarım turunda *"(c) dalı B3'ten önce de ölüydü, çünkü `normalize_tr("MATEMATIK")`
Türkçe locale ile `"matematık"` üretir"* diye bir hipotez kuruldu. **Ölçüm çürüttü:**
`osym_exam_engine.py:1387` → `subject = question.subject_area.lower()`. Yani `sp.subject`
**küçük harf** ("matematik") üretiyordu, `normalize_tr("matematik")` = `"matematik"`,
eşleşme **True**. Dal B3'ten önce **canlıydı**; B3 öldürdü.

Sonuç iki yönde bağlayıcı:
- (c)'nin onarımı bir *gerileme onarımıdır*, bir *iyileştirme değildir*.
- `ders` alanı **küçük harf** saklanmalıdır (motorun ürettiği biçim), karşılaştırmada
  `.claude/rules/case-convention.md` kanonik yardımcıları kullanılmalıdır.

## 2. Tasarım

### 2.1 Model — kimlik alanları

`backend/models/exam.py:83`

```python
class KonuPerformansi(BaseModel):
    """Konu bazlı performans modeli"""

    konu: str
    toplam_soru: int
    dogru_sayisi: int
    yanlis_sayisi: int
    bos_sayisi: int
    basari_yuzdesi: float
    ortalama_sure: float | None = None
    # B3 FAZ 3 — kimlik alanları SONA + varsayılanlı.
    # `SubjectPerformance`'taki aynı disiplin (osym_exam_engine.py:113-117):
    # başa/ortaya eklenen alan pozisyonel çağrıyı sessizce yanlış alana bağlar.
    # Varsayılanlı olmaları 6 test çağrı yerini geriye uyumlu bırakır.
    ders: str | None = None        # motorun ürettiği biçim: küçük harf 'matematik'
    konu_kodu: str | None = None   # topic_hierarchy.code, örn. 'MAT.FON'
```

Üretici — `backend/core/osym_exam_engine.py:2180`:

```python
KonuPerformansi(
    konu=sp.topic_name or sp.subject,
    ...
    ders=sp.subject,
    konu_kodu=sp.topic_code,
)
```

**Neden `topic_hierarchy.subject_area` değil `sp.subject`:** ölçüldü — `topic_hierarchy`
satırlarında `subject_area` **NULL** (`MAT|Matematik||1`, `KIM|Kimya||1`). Ders kimliği
yalnız `question_metadata.subject_area` üzerinden gelir, o da motorda `sp.subject`'tir.

### 2.2 Tüketici (a) — IRT agregasyonu

Yeni yardımcı, mevcut `_get_subject_irt_aggregate` **silinmeden** eklenir:

```python
async def _get_irt_aggregate(
    *, topic_code: str | None, ders: str | None
) -> dict[str, float | int]:
    """IRT agregasyonu — konu kodu varsa konu bazlı, yoksa derse düşer."""
```

- `topic_code` doluysa: `JOIN topic_hierarchy ON th.id = qb.primary_topic_id
  WHERE th.code = :topic_code`
- boşsa: `WHERE question_metadata.subject_area = subject_db(ders)`
- Cache anahtarı **ayrışır**: `irt_aggregate:topic:{code}` / `irt_aggregate:subject:{DERS}`
  (aynı anahtar altında iki farklı semantik veri tutmak sessiz karışma üretir)
- Çağrı yerleri: `:474` ve `:1167` → `_get_irt_aggregate(topic_code=kp.konu_kodu, ders=kp.ders)`

**Eski fonksiyon neden kalıyor:** `tests/fast/test_advanced_reports_split.py` 12 yerde
onu çağırıyor ve #485 split JOIN yapısını çiviliyor. Silmek o bekçiyi düşürür.

🔴 **Yeni kör nokta ve kapatılması:** `_get_irt_aggregate` yeni bir sorgudur ve
`test_advanced_reports_split.py`'nin kapsamı **dışındadır**. Aynı sınıftan bir split
kaçağı orada tekrar edebilir (bkz. `L-s230-ast-sayaci-ham-sql-goremez` ve ES şema
kaçağı vakası). Bu yüzden yeni fonksiyon için **kendi split bekçisi** yazılır:
sorgu canlı şemaya karşı **koşturulur**, metni okunmaz.

### 2.3 Tüketici (b) — kovalama-değişmez ZPD ortalaması

`:761` ve `:869/873`:

```python
# B3 FAZ 3: soru-AĞIRLIKLI ortalama. Ağırlıksız `Σ/len(kova)` kova sayısına
# bağlıdır; kardinalite 1->13 olunca ortalama sessizce kayar (ölçüldü: +9,91).
# Ağırlıklı biçim kovalamadan BAĞIMSIZDIR: aynı sınav ister 2 ders kovası ister
# 13 konu kovası olarak verilsin, sonuç aynıdır.
toplam_agirlik = sum(z["agirlik"] for z in konu_zpd_analizleri)
if toplam_agirlik:
    ort_seviye = sum(z["mevcut_seviye"] * z["agirlik"] for z in ...) / toplam_agirlik
else:
    ort_seviye = 0.0
```

- Ağırlık = `kp.toplam_soru`; her `konu_zpd_analizleri` kaydına `agirlik` eklenir
- `toplam_agirlik == 0` → `0.0` (sıfıra bölme; mevcut kodda `len()==0` zaten `if not
  konu_perfs` ile korunuyor ama ağırlık toplamı ayrı bir sıfır kaynağıdır)
- **Yanıt sözleşmesi:** `agirlik` yeni bir anahtar. Frontend sözleşmesi eklemelidir
  (mevcut anahtarların hiçbiri kaldırılmaz), `test_advanced_reports_schema_parity.py`
  ile uyum doğrulanır.

### 2.4 Tüketici (c) — ders dalı

`:934` ve `:1051`:

```python
from core.turkish_nlp_utils import subject_key
...
ders_anahtari = subject_key(kp.ders)          # 'MATEMATIK' | 'matematik' -> 'matematik'
if ders_anahtari == "matematik":
    ...
elif ders_anahtari == "turkce":
    ...
```

- `normalize_tr` **kullanılmaz** — `.claude/rules/case-convention.md` yasağı: subject
  identifier'a `normalize_tr` uygulanmaz (Türkçe locale `I→ı`). Ölçüldü:
  `subject_key` yalnız `.strip().lower()` yapar (`turkish_nlp_utils.py:89`), Türkçe
  eşleme uygulamaz — ASCII tag için doğru olan budur.
- 🔴 **Kardeş sessiz kusur:** mevcut `elif "türkçe" in ...` dalı, kanon değerle
  **hiçbir zaman** eşleşemez. Ölçüldü (`SELECT DISTINCT subject_area FROM
  question_metadata`): kanon küme **{`KIMYA`, `MATEMATIK`}** — ASCII, `TURKCE`
  biçiminde. `subject_key("TURKCE")` = `"turkce"` ≠ `"türkçe"`. Dize `"turkce"`
  olarak düzeltilir.
  **Doğrulama sınırı, dürüst kayıt:** canlı DB'de `TURKCE` satırı **yok**, dolayısıyla
  bu dal canlı E2E ile doğrulanamaz. Sentetik `KonuPerformansi(ders="TURKCE")` ile
  **birim testte** çivilenir ve bu sınır denetime yazılır.
